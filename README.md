# TwiPay

TwiPay is an Octalve-owned financial, utility-payment and event-ticketing platform designed for `twipay.co` while remaining provider-independent and suitable for standalone licensed/white-label deployments. TwiPay is independent from COOV and has no OpenAI/ChatGPT runtime dependency.

## Architecture at a glance

- `apps/web` — customer Next.js application
- `apps/admin` — isolated operations/compliance/finance Next.js application
- `apps/api` — NestJS/Fastify core API
- `apps/worker` — BullMQ/background reconciliation and notification worker
- `packages/database` — Prisma schema and PostgreSQL migrations/invariants
- `packages/ledger` — immutable double-entry money invariants
- `packages/security` — sessions, cryptography, MFA and shared security rules
- `packages/contracts` — provider-neutral contracts
- `packages/providers` — provider adapters only; business logic remains TwiPay-owned
- `docs` — architecture, ADRs, security, provider, runbook, deployment and release records

TwiPay uses integer minor-unit accounting and a sealed double-entry ledger. Wallet availability is derived from ledger state plus holds; no mutable wallet balance is the accounting source of truth. Ambiguous provider submission remains `UNKNOWN` until same-provider requery/reconciliation; TwiPay never blindly switches providers after an uncertain submission.

The previous ErhaPay/BillPadi/Data Arena material is reference-only. Do not copy its runtime architecture or reintroduce legacy mock branding/data.

## Release toolchain

- Node.js `24.21.0` / Node 24 LTS line
- pnpm `12.9.1` via Corepack
- PostgreSQL 18
- Redis/BullMQ
- Docker for release/container qualification

A genuine `pnpm-lock.yaml` must be generated by a real network-enabled `pnpm install` and committed before dependency-backed CI/container qualification. Never manufacture a lockfile.

## Local setup

```bash
corepack enable
pnpm install
cp .env.example .env
# Fill LOCAL-ONLY values. Never commit .env or live provider credentials.
docker compose up -d postgres redis
pnpm db:generate
pnpm db:migrate
pnpm dev
```

## Mandatory verification

```bash
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:repo
pnpm test:history-secrets
pnpm e2e
```

PostgreSQL 18 migrations/integration/concurrency, Redis/BullMQ, browser E2E, provider sandbox, container/SBOM/CodeQL/DAST, backup-restore, rollback, load/failure and staging checks are mandatory release gates. A gate that was not actually executed is `BLOCKED`, not `PASS`.

High-risk flags `events.refunds` and `operations.organizer_payouts` are fail-closed and must remain disabled until the complete MFA/RBAC/maker-checker/accounting/provider/integration/E2E/staging activation gates pass.

Start with `TWIPAY_NEW_CHAT_CONTINUATION_BRIEF.md` when present in a handoff, then `BATCH_04_VERIFICATION.md`, `docs/README.md`, `SECURITY.md`, architecture/security ADRs, migrations and the latest Batch 5 verification/release records before changing authentication, financial or provider behavior.
