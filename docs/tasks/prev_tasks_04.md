### Task 04.7: Authentication review — `64fae61`, `db60f4f`, `af50b18`
Journeys driven in a real browser (Playwright) against the production builds, with screenshots:
registration validation, register, verify (wrong then correct code), dashboard, reload, logout and server-side session
revocation, route guards, wrong/unknown-credential login, duplicate registration, password reset, rate limiting.

| Bug | Root cause | Fix |
| :--- | :--- | :--- |
| Dashboard crashed for every user after verification | 62 `(void 0)` statements on their own line were joined to the previous line by automatic semicolon insertion (`useQuery({...})(void 0)`) | Rewritten as `void 0;` (43 files) |
| Rate-limit rejections returned HTTP 500 | `@fastify/rate-limit` throws a plain `Error` with `statusCode`; Nest maps only `HttpException` | `errorResponseBuilder` throws `HttpException` 429 `{ code: RATE_LIMITED, retryAfterSeconds }` |
| Correct verification code rejected after one wrong code | A rejected code stayed in the `InputOTP`, which only overwrites its last slot when full | Field cleared after a failure (email verification and 2FA) |
| Every auth failure said "Something went wrong" | The API replies `{ code }`; the UI read `message` from a possibly undefined body | `authErrorMessage()` maps the codes, handles a missing response and shows the wait time |
